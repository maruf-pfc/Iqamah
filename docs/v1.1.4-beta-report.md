# v1.1.4 Beta execution report

2026-10-13. This report covers the completed mobile/data-safety batch, **not full
completion of the entire hardening specification**.

1. **Overall status:** blocked for distribution. Android-first implementation
   progressed; authoritative accuracy and real-device/upgrade evidence are missing.
2. **Bugs fixed:** SQLite coercion/default data loss; orphan Qaza loss; preferences
   written after records; false native export success; lost imported owner/metadata;
   partial calculation settings reset; silent district-save failure; stale APK assets.
3. **Features completed in this batch:** restore preview/confirmation, merge/replace,
   native file picker protocol, acknowledged native sharing, recoverable restore,
   bilingual Home approximate caution countdown.
4. **Duplication removed:** shared native request correlation/listener handling and
   shared button geometry. Requested redundant Settings timetable/guide entries
   removed; Analytics is in Settings, Guide in bottom navigation. Daily Salah card
   left stripes removed. Dormant SQLite is preserved, not deleted.
5. **Backup/restore:** schema 2.0.0 exports active prayer records, notes, Tasbih flags,
   Qaza and preferences. Plaintext sensitive files. Journaled multi-key rollback,
   startup recovery and failure blocking. See `backup-and-recovery.md`.
6. **Historical support:** integer SQLite v1, canonical web 1.1.0, existing string
   aliases 1/1.0.0 and current 2.0.0. Distinct shape fixtures are synthetic; alias
   artifacts have not been found. Unsupported future versions fail closed.
7. **Upgrade:** unchanged `com.example.mobile`, code 6, name 1.1.4-beta.1 and asset
   loading mechanism. Prior certificate/artifact unavailable; `adb devices` empty.
   **No actual upgrade preservation verification.**
8. **Prayer methodology/sources:** existing offline adhan engine retained; default
   Karachi/Hanafi. IFB fetch failed; no official convention/fixture certified.
9. **District validation:** 64 community-source reference points retained; official
   coordinate/name/division validation remains unresolved.
10. **Discrepancies:** no measured official timetable comparison or justified
    tolerance established. Unresolved accuracy remains release blocking.
11. **Religious review:** Qaza invariants tested. Unsupported IFB, tolerance and
    universal-reward claims qualified; expert source/content approval pending.
12. **In-app documentation:** existing bilingual guidance updated for actual storage,
    backup/restore, upgrade uncertainty, recovery and approximate caution assumptions.
13. **Security/privacy:** restricted file-origin native protocol, filename/size checks,
    no new telemetry/server, no sensitive logging, fail-closed signing. No full
    dependency-vulnerability audit or physical plugin security certification.
14. **Checks:** 76 Vitest tests/12 files; 10 Flutter tests; vue-tsc, ESLint, Oxlint and
    Flutter analysis passed. Production build, clean Android debug build and APK
    extraction check passed. Release build intentionally failed without credentials.
    Geometry checked small phones; screenshot tool unavailable. iOS not built on Linux.
15. **Artifacts:** `client/dist/index.html`, `mobile/assets/web/index.html`,
    `mobile/build/app/outputs/flutter-apk/app-debug.apk` (154,333,519 bytes).
    Debug artifact is verification-only; no public release artifact produced.
16. **Changed files:** Vue App/Dashboard/Settings/Guide, timetable/district components,
    CSS/localization/prayer store, backup/prayer services, new restore/native-file
    services and schema/UI tests; Flutter WebView/bridge/tests; Android signing guard;
    CI; regenerated web bundle; APK verification script; README/CHANGELOG/CONTRIBUTING
    and these release/backup/report documents. No retired backend reintroduced.
17. **Remaining blockers:** official timing/geography, scholarly review, real native
    share/import/upgrade/lifecycle/text-scaling QA, existing signing credentials;
    active Tasbih counter/targets, standalone notebook and notifications unfinished.
    Native light-theme chrome sync, full visual/device review and performance audit
    remain incomplete. Pixel-perfect behavior is **not** claimed.
18. **Recommendation:** **blocked**. Resolve acceptance-critical evidence before any
    controlled public beta; use debug APK only for local engineering verification.

## Standards review

Initial review found **2 hard-standard gaps, 2 concrete defects and 3 possible
smells**. Native protocol coverage, semantic release styling, partial restore,
filename overrides, typed preferences and shared request handling were corrected.
Follow-up found no residual high-risk issues in its reviewed scope. The worst
concrete standards-axis defect was ignored/reset partial calculation preferences.

## Spec review

Initial review found **3 concrete defects** (imported identity/metadata loss,
partial timing semantics, gender state before persistence), all corrected.
Follow-up found **1 further concrete defect**: JSON envelope limit reduced usable
native export size. The guard now permits worst-case escaping while retaining the
decoded-content cap, with a Flutter regression test. The worst remaining spec-axis
concerns are the explicitly disclosed accuracy/upgrade/device acceptance blockers,
not an assertion that this partial batch is release ready.
